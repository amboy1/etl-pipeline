# High-Performance Distributed ETL Pipeline

Распределенный асинхронный ETL-пайплайн для высокоскоростной потоковой обработки и агрегации больших CSV-файлов (от десятков мегабайт до десятков гигабайт) с использованием архитектурного паттерна MapReduce на базе Celery Chord, Redis и Django.

---

## 1. Архитектура и ключевые особенности

### 1.1. Паттерн MapReduce на базе Celery Chord
Обработка файла не загружает весь датасет в оперативную память, а распределяется по независимым параллельным процессам:
* **Orchestrator (`process_file`)**: вычисляет размер файла и рассчитывает байтовые границы для указанного количества параллельных воркеров (1, 2, 4, 8). Инициализирует метаданные в базе данных и кэше Redis.
* **Map Phase (`process_chunk`)**: параллельные воркеры позиционируются на заданный байтовый смещение (`seek`), выполняют интеллектуальное выравнивание начала строки (пропуск обрубка предыдущей строки или заголовка CSV) и потоково построчно агрегируют финансовые показатели и категории до достижения конечной байтовой границы чанка.
* **Reduce Phase (`combine_chunk_results`)**: функция обратного вызова (Celery callback), запускаемая автоматически брокером по завершении всех Map-задач. Суммирует промежуточные структуры данных, формирует итоговые финансовые метрики и сохраняет финальный статус в БД и Redis.

### 1.2. Константное потребление памяти O(1)
Воркеры считывают данные через файловые потоки блоками по строкам без физического дублирования или разделения исходного файла на диске. Это гарантирует стабильную работу при любых размерах входных файлов без риска возникновения `MemoryError` или Out-Of-Memory (OOM) killer.

### 1.3. Высокоскоростной трекинг прогресса в Redis
Для исключения блокировок и высокой нагрузки на реляционную базу данных во время параллельной обработки миллионов строк:
* Воркеры инкрементируют общий счетчик обработанных строк атомарными командами `HINCRBY` с шагом в батч (`PROGRESS_BATCH_SIZE = 10 000` строк).
* Эндпоинт опроса прогресса (`/api/progress/<id>/`) читает данные напрямую из оперативной памяти Redis за доли миллисекунды.
* Запись в базу данных SQLite/PostgreSQL выполняется только в моменты смены глобальных статусов (старт, успешное завершение, сбой).

## 4. Установка и запуск

### Вариант 1: Запуск через Docker Compose (Рекомендуемый)

Данный способ автоматически разворачивает изолированное окружение с Redis, веб-сервером Django и воркером Celery.

1. **Клонирование репозитория и переход в директорию**:
   ```bash
   git clone <repo-url>
   cd etl-pipeline
   ```

2. **Подготовка файла конфигурации**:
   ```bash
   cp .env.example .env
   ```

3. **Сборка и запуск контейнеров в фоновом режиме**:
   ```bash
   docker compose up --build -d
   ```

4. **Проверка статуса сервисов**:
   ```bash
   docker compose ps
   ```

5. **Просмотр логов**:
   ```bash
   # Логи всех сервисов
   docker compose logs -f

   # Логи воркера Celery
   docker compose logs -f celery_worker
   ```

6. **Остановка сервисов**:
   ```bash
   docker compose down
   ```

Веб-интерфейс доступен по адресу: `http://localhost:8000/`.

---

### Вариант 2: Локальный запуск (macOS / Linux)

#### 1. Предварительные требования
* Python 3.11+
* Redis Server (установлен и запущен локально на порту 6379)

#### 2. Создание виртуального окружения и установка зависимостей
```bash
python3 -m venv venv
source venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

#### 3. Настройка переменных окружения
```bash
cp .env.example .env
```

#### 4. Применение миграций базы данных
```bash
python manage.py migrate
```

#### 5. Запуск Redis
```bash
# macOS (через Homebrew)
brew services start redis

# Linux (systemd)
sudo systemctl start redis
```

#### 6. Запуск воркеров Celery
Для систем macOS рекомендуется запуск независимых процессов с пулом `solo`:
```bash
for i in {1..8}; do
  venv/bin/celery -A etl_project worker -l info --pool=solo --pidfile=w$i.pid --logfile=w$i.log -n w$i@%h --detach
done
```
*(Для остановки фоновых воркеров: `pkill -f "celery -A etl_project"`)*

Для Linux систем доступен запуск в едином процессе:
```bash
celery -A etl_project worker -l info --concurrency=8
```

#### 7. Запуск веб-сервера разработки Django
```bash
python manage.py runserver 0.0.0.0:8000
```

## 5. Конфигурация (.env)

| Переменная | Значение по умолчанию | Описание |
|---|---|---|
| `DJANGO_SECRET_KEY` | - | Секретный ключ приложения Django |
| `DJANGO_DEBUG` | `True` | Режим отладки Django |
| `DJANGO_ALLOWED_HOSTS` | `localhost,127.0.0.1,*` | Разрешенные хосты |
| `CELERY_BROKER_URL` | `redis://localhost:6379/0` | URL подключения Celery к брокеру сообщений |
| `CELERY_RESULT_BACKEND` | `redis://localhost:6379/0` | Хранилище результатов задач Celery |
| `CELERY_CONCURRENCY` | `8` | Размер пула параллельных процессов Celery |
| `DEFAULT_NUM_CHUNKS` | `4` | Количество чанков по умолчанию для обработки файла |
| `PROGRESS_BATCH_SIZE` | `10000` | Шаг инкремента счетчика строк в Redis |
| `PROGRESS_TTL` | `86400` | Время жизни ключей прогресса в Redis (в секундах) |

## 6. Генерация тестовых наборов данных

В проект включен потоковый генератор синтетических CSV-файлов, способный формировать датасеты любого объема (100 тыс. строк, 1 млн строк, 50 млн строк) без переполнения памяти.

Схема данных CSV:
`transaction_id,date,user_id,amount,category`

Примеры команд:

```bash
# Генерация файла на 1 000 000 строк (~75 МБ)
python scripts/generate_data.py --rows 1000000 --output data/transactions_1m.csv

# Генерация файла целевого размера 500 МБ
python scripts/generate_data.py --size-mb 500 --output data/transactions_500mb.csv

# Быстрый тестовый датасет на 50 000 строк
python scripts/generate_data.py --rows 50000 --output data/transactions_small.csv
```

## 8. Спецификация REST API

### 8.1. Загрузка файла
* **URL**: `/api/upload/`
* **Метод**: `POST`
* **Параметры формы (`multipart/form-data`)**:
  * `file`: CSV-файл
  * `num_chunks` (опционально, int, по умолчанию `4`): количество параллельных потоков
  * `autostart` (опционально, bool, по умолчанию `true`): автоматически запустить обработку
* **Пример ответа**:
  ```json
  {
    "success": true,
    "file_id": 42,
    "filename": "transactions_1m.csv",
    "file_size_mb": 74.82,
    "celery_task_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
    "status": "PROCESSING"
  }
  ```

---

### 8.2. Опрос прогресса в реальном времени
* **URL**: `/api/progress/<int:file_id>/`
* **Метод**: `GET`
* **Источник данных**: Redis In-Memory Hash (с переключением на SQLite при отсутствии ключа)
* **Пример ответа**:
  ```json
  {
    "source": "redis",
    "file_id": 42,
    "status": "PROCESSING",
    "processed_rows": 640000,
    "total_rows": null,
    "progress_percent": null,
    "error_message": null
  }
  ```

---

### 8.3. Получение итоговой аналитики
* **URL**: `/api/details/<int:file_id>/`
* **Метод**: `GET`
* **Пример ответа**:

### 8.4. Ручной перезапуск обработки
* **URL**: `/api/start/<int:file_id>/`
* **Метод**: `POST`
* **Параметры формы**:
  * `num_chunks` (опционально, int): количество чанков (1, 2, 4, 8)

## 9. Функционал веб-интерфейса

* **Drag-and-Drop загрузчик**: поддержка файлов произвольного объема с валидацией расширения `.csv`.
* **Интерактивный селектор параллельности**: выбор 1, 2, 4 или 8 воркеров перед отправкой файла.
* **Динамический прогресс-бар**: автоматический поллинг статуса с частотой 500 мс и плавной анимацией заполнения.
* **Карточки файлов в реальном времени**:
  * Расчет скорости обработки (строк/сек).
  * Время выполнения с точностью до сотых долей секунды.
  * Итоговый финансовый оборот (в рублях).
  * Раскрывающийся аккордеон с распределением сумм по категориям транзакций.
* **Индикаторы системного состояния**: отображение активности брокера Redis и фоновых воркеров.
